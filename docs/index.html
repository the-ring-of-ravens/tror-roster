Session History

A new session history chart has been added to the Sessions tab! It shows the number of sessions over time, with filters for session type and regiment.

The above images show the general trend of session activity of all time, and all regiment sessions hosted over the past year.

When making this, I had a general goal of making it look similar to a weather forecast. I really liked the 3-day/week/month view. When I did include the week view, it was really silly because there's usually zero to one sessions hosted each day, which didn't give any meaningful information. But the 3-month/year/all-time works really well.

The above images show bootcamps hosted over the past 3 months, and the recruitment events hosted over the past year.

I don't like that the formula to calculate the curve sometimes dips below 0, but I haven't found a better one so I guess we'll just have to live with it.

20 July 2026

First Draft of Soldier Point Chart

I created a line graph of a soldier's point history over time! This took me several days to perfect. There was a lot of work that had to be done behind the scenes.

First, I created a subpage on the statistics tab that you could navigate to from a soldier's profile. I wasn't completely set on having the profile be here, so the buttons weren't completed and the spacing was a little off.

Next, I made a line graph showing the point history over time. This was by far the most difficult part, but was mostly solved by the data entry I did beforehand. Here's how I created the graph:
• Find the soldier's join date & all sessions attended
• Starting at the current date and current points, work right to left
• For each session, mark a point and then move down a step
• If the soldier's join date is reached, stop
• If the soldier's points reach zero, stop
• Connect all the points with a line

One thing that I struggled with was getting the line to actually show up on charts with hundreds of points, such as the one below.

I realized this was a problem with the way the line was being drawn, and also realized that it makes more logical sense for the lines to be straight along the axises (axes?) instead of going directly from one point to the next. You're not going to earn half a point over the course of a week!

I also added markers for when each soldier ranked up. Want to know a secret? The regular rankups are just estimates, not the actual rank-up dates. When a soldier reaches a certain point threshold, the website says they get promoted whether that change is actually made in Discord or not.

This is not the case for officer rankups, though. Those are put in manually because I can't think of a reliable system to track them automatically. But since our officer team is relatively small, their rankups aren't difficult to record.

And the change works for all soldiers now!

16 May 2026

The Plan

Two weeks of thinking (and studying for finals) later, I finally completed the plan for this website.

A few early ideas I had were to have the GitHub page somehow contain the database, or use MongoDB or a similar database website to store the data, and users would log in to submit attendance or update other information. Then I remembered: managing user accounts and keeping data safe and private on a PUBLIC GitHub site is the worst idea ever. I didn't want to deal with users, but I wanted some way for officers to securely submit sessions and update the roster if this ever did become the official roster.

Then I had a thought. Is there a way for a public website to access a private Google Sheet? If so, users could safely be added to the sheet using the same Google accounts they use to update the official roster.

And wouldn't you know it, there is a way! Here's how it all works:

The User (on a Google account)is added to the list of members who can submit the Google Form (Did you know that's a thing? Adding individual users who can submit forms? I didn't). They input the attendance information (session name, date, host dropdown, attendees, counted) and submit the form.

The Spreadsheet gets a new row added when the form is submitted. A notification is sent to the Google Apps Script "on form submission" to process the data:
• Check if all soldiers exist (and all names spelled correctly)
• If not, halt the process and flag it in the sheet and website
• Update the date of the most recent session for each soldier
• If the points are counted (✅), add a point to each soldier
• If they aren't counted (🟡), add a point to the host only
• If the session title contains a regiment name, add regiment points to all
• Compare each soldier's new point count to the rank key
• If a soldier has enough points to rank up, add to rankup list
• Review all sessions and update sessions hosted in the past 30 days per officer
• Mark the session as processed in the sheet

The Website is basically a pretty front-end version of the spreadsheet. It accesses the session data, the soldier data, and the rank key to calculate and display the information in a user-friendly way.
